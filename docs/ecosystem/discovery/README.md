# Discovery

**Purpose:** The discovery canon as entity files: one locked statement, candidate section, knowledge-base entry, open question, gaps-register entry or session note per markdown file. The file is the card on the Discovery Canvas; frontmatter carries id, kind, title, status, tags and revision, the body carries the text verbatim.

**Spec:** [`../thinking/2026-09-11_discovery-canvas-spec.md`](../thinking/2026-09-11_discovery-canvas-spec.md), sections 4 to 7 (storage layout, entity files, write policies, revisions).

**This is for:** Entity files created by the in-app importer (spec section 5.7), by the app's "new statement / question / note" actions, or by hand in the same format. Generated long views (`*-VIEW.md`) and statement history files (`SNNN.history.md`) also live here.

**This is NOT for:** The canonical cores (→ `../universe/`, read-only, one card per whole file), canvas layout, edges, tags or native material (→ `../canvas/`), or the original long documents these entities are cut from (→ `../thinking/`; the importer never modifies them).

## Folders

| Folder | Kind | ID | File name | Write policy |
|--------|------|----|-----------|--------------|
| `statements/` | Locked statement | `stmt:N` | `SNNN.md` | `revisioned` |
| `candidates/` | Candidate section | `cand:<source-slug>/<letter>` | `<source-slug>/<letter>.md` | `editable` |
| `kb/` | Knowledge-base entry; non-numbered KB section | `kb:N`; `kbx:<slug>` | `KB-NNN.md`; `X-<slug>.md` | `editable` |
| `questions/` | Open question | `cq:NNN` | `CQ-NNN.md` | `editable` |
| `gaps/` | Gaps-register entry | `gap:N` | `G-NNN.md` | `editable` |
| `session-notes/` | Non-statement log material | `log:<slug>` | `<slug>.md` | `editable` |

## Rules

- One ID per thing; the ID comes from the file name and survives title changes. A colliding `id` is reported by the app, never silently renamed.
- Frontmatter is the single home for status and tags. Tags are written as paths; `../canvas/tags.json` maps stable tag IDs to those paths.
- `revisioned` files keep their number on edit: `revision` increments and the previous text goes to the sibling history file (spec section 7). `editable` files are rewritten whole. Nothing here is append-only.
- `*-VIEW.md` files are generated by the Claude Code sweep (spec section 14) and carry a "generated, do not edit" banner.
- The canvas app writes only under this folder and `../canvas/`; commits are the sweep's job, pushes are Stefan's.
