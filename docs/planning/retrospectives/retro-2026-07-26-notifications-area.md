## What went well

- **The dispatcher chose construction over discipline.** `INSERT INTO public.notifications` appears at ~38 sites across 11 migrations. Per-emitter checking meant 38 edits and a standing invitation to forget the 39th; one `BEFORE INSERT` trigger catches every writer **by construction**, including the audited admin path, and every future contract inherits suppression for free. This is the NC-1 precedent applied to the write side.
- **Suppression costs nothing downstream, with no second mechanism.** Because a muted notification is never written, N-C's `AFTER INSERT` hint trigger simply never fires — the realtime saving falls out of the design rather than being engineered separately.
- **Failure direction was chosen per consequence, not by habit.** `ds5_may_deliver` fails **open**; N-C's nudge fails **quiet**. Deliberately opposite: N-C's failure mode is *cost*, N-D's is a *missed notification* — invisible to the member, leaving no trace — whereas an unwanted one is visible and recoverable. The asymmetry is stated in the migration so it reads as a decision rather than an accident.
- **A measurement changed a decision instead of decorating one.** N-C measured the largest real announcement at **857 delivery rows against a reachable 1,274**, proving fan-out cost tracks **headcount, not concurrency** — so "few members are online" is not a mitigation. That turned the platform nudge into an operator toggle defaulting off, and N-D then put the cost line **on the console where the person flipping the switch sees it**, rather than leaving it in a session bridge.
- **The preference home was adjudicated on paper before any code — and the filing was wrong about its own shape.** Filed as a three-way tension; verifying each claim at its cited line found a **fourth**, with `communication.md` contradicting *itself* (§Entities `:44` vs its §L3 dependency column `:126`). That is why it survived four cycles: every document was locally coherent. The ruling turned on a hard constraint rather than taste — a preference row must FK a DS-5 table, and in Core that FK points Core→Domain, which `platform/CLAUDE.md:38` forbids with a *named* failure mode.
- **ND-2 caught a feature that would otherwise have shipped as a dead page.** Read strictly against the Notifications vertical's own §7 checklist, **all six categories are lawfully "transactional"** — NTF-10 would have rendered a preferences page with every switch disabled. Suppressibility became its own axis (`member_suppressible`) instead of re-labelling `lawful_basis`, which would have moved a legal field for a cosmetic reason.
- **NB-7's override paid off twice.** Early-executing ADR-U039's own Phase-4 disposition (replace-then-remove, so the capability was never absent) left `supabase_realtime` **empty** — retiring the legacy `postgres_changes` full-row push entirely, which is the end-state U039's §Alternatives always implied.

## What to learn (carried forward)

1. **The sibling-assertion defect has now happened three times. It is a class, and it needs a mechanical check rather than a norm.** The shape: a change to shipped semantics leaves a *sibling* suite still pinning the old shape. **N-A** — a walk-wording fix neutralised the forum tombstone copy and left two A-COM E2E specs asserting the old text. **N-B** — a payload change left a stale assertion, found only by N-C's sweep. **A-COM RIDER-3** — a topology change left a sibling assertion, found only by N-D's TASK-INT-02 triage. Two of the three were caught only by a *later area's* sweep, and **both first read as environment faults**, which is the expensive part: the diagnosis cost far exceeded the fix. **Proposed check:** a line in the migration template requiring the author to grep the suite for assertions naming any object whose semantics the migration changes, and to **list them in the migration header**. RIDER-3's header named only its own guarded test, which is exactly how its sibling was missed.
2. **Two false greens, each caught only because a paired assertion failed.** N-C shipped a vacuous test; N-D's `admin_send_notification` check passed its *muted* half because the RPC was **refused** (called as `service_role`, where `is_platform_admin()` is false) — not because anything was suppressed. Only the failing "delivers when unmuted" twin made the false green visible. **Rule to carry: every "this does not happen" assertion needs a "this does happen" twin in the same test**, or it can pass for the wrong reason indefinitely.
3. **An ADR's status line lags its own acceptance condition — twice now, so this is a pattern, not an oversight.** **U039** sat at `Proposed` through four realizations across three areas. **U050** read `Proposed (rides the C-F schema gate; Accepted on the gate's named nod)` for five days after that gate merged — its condition was self-executing and nobody executed it. Both were load-bearing while reading as provisional, which is the actual harm: "Proposed" tells a reader the conventions may still move. **Proposed check to carry:** at each cycle close, scan `Status: Proposed` ADRs for one whose stated acceptance condition names an event that has already occurred.
4. **A completion plan is a document agents execute from, and it rots like any other.** N-D amended four canonical docs on the preference-home ruling and **forgot the plan agents actually read** — which still directed preferences to Core in three places, including a DoD checkbox. Separately, that plan asserted a dependency on "IDN-7's preference-persistence pattern" **which does not exist** (IDN-7's realized half is an append-only consent ledger; its preference-shaped half is G-34, unbuilt). Copying the ledger would have made every preference read a `DISTINCT ON … ORDER BY created_at DESC` for no benefit. **Verify a plan's dependency claims against disk before building on them.**
5. **The DoD names an artifact that has three instances.** "Update `CHANGELOG.md`" (`feature-development/SKILL.md:122` and `:140`, `AGENTS.md:85`, `PROCESS.md:201`) never says *which* — root, `hub/`, or `docs/platform/core/`. Across four cycles the area split across two files without anyone noticing: N-B wrote only to `hub/`, N-C and N-D only to root, N-A to neither. Every close-ritual checkbox read "done" and was locally honest. Backfilled at the gate (PRs #299, #300); **the DoD wording is still ambiguous and is the actual fix.**
6. **A silent negative result is a broken check, not a clean one.** Three times during the gate work a grep returned nothing and the correct reading was "my pattern is wrong", not "the thing is absent" — the schema uses lowercase `create table`, and four of six ADR filenames differ from their obvious slug. Each near-miss would have put a confident false claim into a document agents orient from. **Confirm a negative with a positive control before reporting it.**
7. **N-D's Hub half was test-after — a process deviation, surfaced rather than absorbed.** The platform half was properly demonstrated red (21 of 24 failing pre-apply). FEAT-H033 was implementation-first, and all six panel tests plus the adversarial integration test passed on their first run. Nothing is known to be wrong with them; the point is that a suite which has never been red has never been proven to test anything.

Summary: **warm and semi-warm all PASS** (272–402 ms; the binding signal per the A-COM rider), **B1 sign-in PASS** at 2 377 ms, and **deep-cold B2 FAILS on both pages at ~5.5 s** against a 2 500 ms ceiling — recorded as a labelled accepted exception pre-launch. The finding worth carrying: **the cold penalty is not page-specific** — whichever authenticated page loads first after idle pays it, so a *returning* member (~5.5 s) is **2.3× slower than a fresh sign-in** (2 377 ms), which no "first-time visitor" framing captures. An in-pass conclusion blaming `OverviewBoot`'s `BOOT_PATHS` gate was **retracted** when the control run put `/groups` at 5 617 ms — it had compared a cold number against a semi-warm one.
