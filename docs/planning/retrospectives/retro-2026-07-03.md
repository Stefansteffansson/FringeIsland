### Learned

- **A socket message is a hint, never an authority** (ADR-U039, Cycle E): one WebSocket per client, private per-user channels, server-originated signals carrying at most event-type + id, verify-on-signal, durable-state-first with polling as the guaranteed catch-up. First tenant shipped (the session guard); Notifications is the named next tenant.
- **Realtime operational gotchas:** Jest's node environment has no `WebSocket` global (pass the `ws` transport + `realtime.setAuth()` explicitly); the first-ever Realtime use cold-boots the tenant (partition creation) and a channel join in that window can close spuriously.
- **E2E suite-order coupling is real:** `profile.spec`'s scope-global sign-out server-revokes the shared storageState session; later specs must not assume that session is alive server-side. Fresh-logins-per-journey is the antidote (Cycle E's sessions journey does exactly that).
- **Found-and-fixed on `main` (Cycle D):** E2E `global-setup.ts` created the session FIM without `consent_accepted` — latent since #48's S3 gate landed. The gate did its job; the harness hadn't caught up.
- **`auth.sessions` is workable as the session store** below the Platform API: the JWT `session_id` claim officially correlates with its PK; `updated_at` is the reliable last-active signal (`refreshed_at` is not).
- **Right-sized decision records:** the Journal→DS-7 routing was recorded as an L3 adjudication note, not an ADR; Cycle A's lifecycle split as a decision doc. Not everything needs the ADR ceremony — but everything got *a* durable record.
