### Learned

- **Append-only substrates make naive erasure simulations impossible — by design, and that's the lesson.** The red suite's cascade proof deleted the personal group directly and hit `consent_records`' ON DELETE RESTRICT + the `enforce_consent_append_only` trigger (42501 outside the controlled path). The honest fix was the real path: `erase_fim_account`, DeusEx-called — the pattern five sibling suites already carry. Erasure proofs should reach for the house erasure functions *first*, never simulate with bare deletes. (ADR-U034 working exactly as intended; the failed simulation was the substrate's success.)
- **A concurrency AC can be topologically impossible as written.** The racing-finals AC assumed "two racing last required steps" — but linear gating totally orders required steps, so the shape cannot exist; the suite instead races two completes of the *same* final step, exercising the identical row lock. Spec ACs describing concurrency should be checked against the ordering the substrate already imposes.
- **Witnessing a click is not witnessing a change.** The E2E asserted the review-entry click, never its effect — so a button that was clickable-but-inert on real shapes (born inert on legacy-completed; permanently inert after one use) passed. E2E asserts the observable effect, not the interaction.
- **The report-idle friction is a confirmed pattern, not an incident:** 2/3 sub-agents needed a ping before delivering their final report this cycle (3/5 at J-B).

### Lacked

- **A reliable completion signal from sub-agent sessions** (carried from J-B; now n=2 → named threshold in §3).
- **Traveller substance for review to show.** Review shipped honest but thin because the step grammar's Ask collects nothing — the root is substrate, not UI.
