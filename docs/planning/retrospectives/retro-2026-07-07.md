### Learned

- **A v1 contract payload meets its first real consumer at Hub build time.** `get_journey_detail`'s v1 viewer block could not serve H019 STORY-5's "affordance per the payload" rule; the fix was an in-place additive amendment (`20260707145549`), demonstrated red against the applied v1 payload first. Lesson: when a platform contract is spec'd one cycle ahead of its Hub consumer, walk the consuming stories against the payload shape *at spec time*, not just the data.
- **The oracle can overstate substrate guarantees.** B-JRN-003's dual-enrolment "detected" behaviour was app-layer-only in hub-legacy; the substrate never enforced it. J-A homed the one-directional semantic substrate-side (gate Q2) — behaviour-inventory rows need a "where was this enforced?" check before being treated as substrate oracle.
- **The stacked-PR trap:** merging #115 with `--delete-branch` auto-closed stacked #116 (a closed PR whose base branch is deleted cannot reopen). Recovery: successor PR #118 from the same branch (zero new commits; the gate record stays in #116's thread). Rule going forward: **retarget-before-delete, or merge top-down** — never `--delete-branch` mid-stack.
- **Lint can rot on main between sessions.** The upgraded `eslint-plugin-react-hooks` added `set-state-in-effect`, which fails the house load-on-mount pattern — main's lint was already red *before* the J-A session started. Feature-PR DoD catches lint at 6-done, but a dependency upgrade merged without the same gates left main red silently.
- Concurrent full-integration + full-E2E sweeps against the shared dev DB coexisted fine this cycle; the `entry.spec` failure stays a sweep-only flake (3/3 green isolated).

## 3. Decisions taken in this retro

- **`set-state-in-effect` disposition: keep the three per-site suppressions; do not configure the rule off.** Each site carries a justification comment; the rule stays live to catch genuinely wrong new cases. If the suppression count grows past ~5, that's a pattern verdict — restructure the load-on-mount idiom (or codify a wrapped hook) instead of suppressing further. Rationale: three sites is instance-scale, not pattern-scale; blanket-disabling trades real future signal for cosmetic cleanliness.
- **Stacked-PR merge rule adopted:** retarget-before-delete or merge top-down; `--delete-branch` only on the last PR of a stack. Recorded as build hygiene (candidate permanent home: the `feature-development` skill's PR section — see §4).
