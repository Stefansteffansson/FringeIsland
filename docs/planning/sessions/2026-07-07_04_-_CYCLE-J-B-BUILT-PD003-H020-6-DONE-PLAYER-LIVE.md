## Findings / lessons (for the J-B/area retro)

1. **The delegated-build shape worked** — five sub-agent sessions (red suite, three Hub blocks, E2E) with the lead verifying every claim first-hand (re-running suites, re-checking counts) before committing. Two recurring frictions: agents idling without sending their final report (a ping recovers it — happened 3/5 times), and one agent initially fixturing from the wrong seed file (`seeds/05` vs the live sprint1 set — the dossier had flagged exactly this divergence).
2. **A nodded schema-semantic change ripples into sibling suites by design:** the Q1 terminal-status decision invalidated four J-A test assertions (row-deletion withdraw, JSONB step_count, legacy kind strings). Budget the paired-suite adaptation into any gate PR that changes shipped semantics — and record it as labelled adaptation, never silent weakening.
3. **The unit tier cannot see type-seam breaks across modules** (`PlayerStep` imported from a module that didn't export it — ts-jest passed, `next build` failed). Standing confirmation of the "next build is the type gate" rule; it fired at the last gate exactly as designed.
4. **Dev-DB 522s under long sweeps are now a named flake class** (Cloudflare 522 from supabase.co during fixture creation; green isolated). If it recurs, a retry wrapper in the seed helpers is the fix — watch item, not action.
