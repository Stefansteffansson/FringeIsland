# Features — Platform Domain Services

Feature specifications for the seven Platform Domain services (DS-1 World Model, DS-2 Narrative, DS-3 Journeys, DS-4 Content, DS-5 Communication, DS-6 Discovery, DS-7 Intelligence). Each feature uses the Shape Up pitch format with BDD stories embedded as Given/When/Then acceptance criteria.

**Feature ID prefix:** `PD` (e.g., `FEAT-PD001-world-model.md`)
**Template:** `../../../templates/feature-spec.md`

Most domain services are not yet built. See `../../../planning/waves/FERD-CAPABILITY-MAP.md` for current implementation status across the ecosystem.

**FEAT-PD001** is the first Domain-tier feature spec, opening **Cycle D** (private Journal) of the [Phase-3 Identity-completion plan](../../../planning/hub-v2/phase-3-identity-completion-plan.md). The Journal primitive was routed to DS-7 Intelligence at the Cycle D decomposition (2026-07-03; PC-2's Step 3 Q1 carry — see `../intelligence.md` §L3 and its Sources-status amendment). It pairs with the Hub surface [FEAT-H011](../../../products/hub/features/FEAT-H011-private-journal.md), API-first (ADR-U009/U038). **FEAT-PD002** (6-done, built Cycle J-A 2026-07-07) is the **first DS-3 Journeys feature spec**, opening **Cycle J-A** of the [Journeys completion plan](../../../planning/hub-v2/phase-3-journeys-completion-plan.md); it pairs with the Hub surface [FEAT-H019](../../../products/hub/features/FEAT-H019-journey-catalogue-and-enrolment.md) and carries the Groups-area seam fill (`get_group_enrollment_summary` — a DS-3 read composed at the Hub BFF, per the one-way rule) plus the [FEAT-PC016](../../core/features/FEAT-PC016-pending-nominations-read-contract.md) rider on its schema-gate migration. **FEAT-PD003** (6-done, built Cycle J-B 2026-07-07) realizes [ADR-U044](../../../architecture/decisions/ADR-U044-journey-step-model.md) — the step substrate (rows + registries + step-instances), the mechanical migration of the legacy JSONB steps, the same-migration re-point of the catalog/detail contracts, the player contracts (`get_player_state`, `enter_journey_step`, `complete_journey_step`), and the carried FEAT-PD002 Q1 withdraw revisit; it pairs with the Hub player [FEAT-H020](../../../products/hub/features/FEAT-H020-journey-player.md). **FEAT-PD004** (6-done, built Cycle J-C 2026-07-08; gate nodded "yes to all", PR #134) closed **Cycle J-C (Completion & review)**'s platform half — completion detection inside `complete_journey_step` on the transition edge (row-locked, idempotent, `completed_at` stamps once; the solo party flips to `completed`, via-group completion stays traveller-grain per invariants 4 + 8), the V3 durable `journey_completed` notification row, derived per-step/total timing semantics, and additive `completion`/`timing` payload blocks; no new tables/columns/RLS — function re-issues only, including the labelled loosening of the enter/complete status guard to admit `completed`. It pairs with the Hub surface [FEAT-H021](../../../products/hub/features/FEAT-H021-journey-completion-and-review.md). **FEAT-PD005** (6-done, built Cycle J-D 2026-07-08; gate nodded, PR #143 + the separately-nodded rider) closed **Cycle J-D (Group progress & frozen mode)**'s platform half — the area's hardest privacy design shipped demonstrated: the consent-gated group-progress read (invariants 4 + 8 enforced in the contract — sharing is per-enrolment opt-in via the append-only `consent_records`; aggregates derive from sharing members only with an honest basis; no timing, no ordering), the catalog's existing `view_group_progress`/`view_others_progress` grain (no seeding — discovered live-wired at build), the additive `freeze`/`progress_sharing` blocks on `get_player_state`, Q9 lived-record read standing for frozen walks, and the PC013/PC014 freeze cascades re-verified red-first (the bridge-`_14` commission discharged; Q8 closed-vs-archived recorded working-as-intended). It pairs with the Hub surface [FEAT-H022](../../../products/hub/features/FEAT-H022-frozen-mode-and-group-progress.md). **FEAT-PD006** (6-done, built Cycle J-E 2026-07-10; gate nodded, PR #163) opens — and closed — **Cycle J-E (The onboarding arc)**'s platform half — realizing [ADR-U045](../../../architecture/decisions/ADR-U045-onboarding-journey.md) + Amendment 1: onboarding designation as data (a boolean flag with a single-designation partial unique index), the in-place replacement of `enroll_self_in_journey` to admit a Mist iff the journey is the designated onboarding journey (the FIM-only gate holds everywhere else), the `get_onboarding_status()` first-arrival read (Mist-callable, enrolment-absence is the signal), the seeded placeholder onboarding journey (native ADR-U044 steps + the [ADR-U046](../../../architecture/decisions/ADR-U046-step-response-capture.md) takeaway seed via `journeys.takeaway` + per-step `content`), and the JRN-5 transcendence carry-over + ADR-U031 ephemerality as proofs over existing machinery (no new mechanism). It pairs with the Hub surface [FEAT-H023](../../../products/hub/features/FEAT-H023-onboarding-arrival-and-carry-over.md). **FEAT-PD007** (5-in-cycle, decomposed 2026-07-18, in build Cycle J-F — migrations authored and dev-applied, held at the schema gate) opens **Cycle J-F (Step-response capture & review substance)** — the last Journeys cycle before the J-O3 area gate — realizing [ADR-U046](../../../architecture/decisions/ADR-U046-step-response-capture.md): the response payload lands on the per-traveller step-instance (the ADR-U044 §4 lived record realized — traveller-own scoping, transcendence carry-over, and ADR-U031 forgetting come free), the `captures_response` registry column names the Ask-family as data, the dedicated `save_step_response` verb keeps capture orthogonal to completion (optional-always, invariant 3; the enter/complete status guard family extends — frozen/withdrawn refuse, completed admits), `get_player_state` gains byte-additive keys (responses, `captures_response`, `journey.takeaway`), response content stays private-only in Ferd (pinned: the group-progress read never carries it), and `get_own_step_instances_export()` discharges the FEAT-H010 step-instances flag before the first response is ever stored. It pairs with the Hub surface [FEAT-H024](../../../products/hub/features/FEAT-H024-ask-capture-and-review-substance.md).
