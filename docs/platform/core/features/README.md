# Features — Platform Core

Feature specifications for Platform Core (Infrastructure, Identity, Organisation, Governance). Each feature uses the Shape Up pitch format with BDD stories embedded as Given/When/Then acceptance criteria.

**Feature ID prefix:** `PC` (e.g., `FEAT-PC001-auth-service.md`)
**Template:** `../../../templates/feature-spec.md`

Retroactive specs (maturity `6-done`) are being written first to capture already-shipped Platform Core functionality. See `../../../planning/waves/FERD-CAPABILITY-MAP.md` for current implementation status.

FEAT-PC001 is the first forward-looking Platform Core feature spec — the substrate provider consumed by Hub [FEAT-H003](../../../products/hub/features/FEAT-H003-mist-identity-on-arrival.md) (IDN-1). FEAT-PC002 continues it with the departure + transcendence slice (§9 stages 3-4), consumed by Hub [FEAT-H004](../../../products/hub/features/FEAT-H004-mist-transcendence-and-farewell.md) (IDN-2); it is gated on [ADR-U033](../../../architecture/decisions/ADR-U033-mist-ephemerality-reaper.md) + [ADR-U034](../../../architecture/decisions/ADR-U034-consent-record-substrate.md). FEAT-PC003 realises the PC-2 §L3 profile-update capability (own-row read + identity-scope update over `public.users`), consumed by Hub [FEAT-H005](../../../products/hub/features/FEAT-H005-member-profile-and-sign-out.md) (IDN-4). **FEAT-PC004 + FEAT-PC005** are the Cycle A account-lifecycle pair (Phase-3 Identity completion, [plan](../../../planning/hub-v2/phase-3-identity-completion-plan.md)): PC004 is the member-facing read of own account state — a `SECURITY DEFINER` read that bypasses the `is_active` visibility filter for the caller's own row (the platform half of IDN-9, consumed by Hub [FEAT-H006](../../../products/hub/features/FEAT-H006-render-account-state.md)); PC005 is the owner-gated, audited self-service reactivation transition (paused→active, decommissioned terminal; the platform half of IDN-12, consumed by Hub [FEAT-H007](../../../products/hub/features/FEAT-H007-self-service-account-reactivation.md)). PC004 is now `6-done` (IDN-9, built in Cycle A — the off-but-not-closed state realised as `suspended`, an admin hold); PC005 stays `4-ready` but is **parked** (IDN-12 deferred — self-service reactivation pairs with self-pause and needs a deactivation-origin field; see the [account-lifecycle decision record](../../../planning/hub-v2/account-lifecycle-states-decision.md)). Each carries net-new substrate (a `SECURITY DEFINER` function + an additive account route) landing through the schema gate at build. **FEAT-PC006 + FEAT-PC007** are the Cycle B consent/GDPR pair and the **first PC-4 Governance** feature specs: PC006 lands the granular-consent substrate (a `decision` column on the PC-2-owned `consent_records` + a seeded `consent_purposes` catalog) plus the own-subject `get_own_consent_state()` read (consumed by Hub [FEAT-H008](../../../products/hub/features/FEAT-H008-render-consent-state.md), IDN-6); PC007 adds the withdrawability-gated `record_consent_decision()` grant/withdraw write (consumed by Hub [FEAT-H009](../../../products/hub/features/FEAT-H009-update-consent-decisions.md), IDN-7 consent half). Both extend the PC-2-owned `consent_records` (ADR-U034 amendment, schema gate at build); the consent-state capability they realise is attributed to PC-4 by `hub/SPECIFICATION.md` §L3:366 and now enumerated in PC-4's own §L3 (consent row added 2026-06-29), and IDN-7's sharing-controls half is split to a later slice (G-34). **FEAT-PC008** is the **Cycle C** data-export/GDPR slice — a synchronous own-subject `get_own_data_export()` that assembles the caller's Core-owned data (profile/account, consent history, memberships) into one versioned `jsonb` document + a durable export-event record, consumed by Hub [FEAT-H010](../../../products/hub/features/FEAT-H010-download-my-data.md) (IDN-8); the data-export capability is now enumerated in PC-4's §L3 (added 2026-06-30, **G-35 narrowed to its feature-flag remainder**), and Domain-owned data (enrolments, …) plus the Journal are forward-seam sections. Net-new RPC → schema gate at build. **FEAT-PC009** is the **Cycle E** sessions slice and closes the G-29-routed PC-2 reciprocation gap (`hub/SPECIFICATION.md` §L3 IDN-11): own-subject `get_own_sessions()` + `revoke_own_session()` over the `auth.sessions` substrate (`admin_force_logout` is the mechanics precedent; feasibility gate passed 2026-07-03, [plan](../../../planning/hub-v2/phase-3-identity-completion-plan.md) row E), plus the server-originated `session_revoked` hint on a private channel — the first tenant of the [ADR-U039](../../../architecture/decisions/ADR-U039-realtime-socket-doctrine.md) socket doctrine, consumed by Hub [FEAT-H012](../../../products/hub/features/FEAT-H012-per-device-sessions.md). New SECURITY DEFINER functions + `realtime.messages` policies → schema gate at build. **FEAT-PC010** is the **first PC-3 Organisation** feature spec, opening the Groups area (**Cycle G-A**, [Groups completion plan](../../../planning/hub-v2/phase-3-groups-completion-plan.md)): `create_engagement_group()` (atomic group + role-instances + creator membership + Steward binding, per the ADR-U016 composed invariant), `get_group_detail()` (visibility-honest read with the viewer `can_manage_settings` capability flag), `update_group_settings()` (permission-gated partial update; the two visibility toggles independent) — plus the ADR-U038 direct-write narrowing on `public.groups` and the idempotent `FringeIsland Members`/`DeusEx` seeding repair (the substrate-audit C3-1 fresh-DB concern, PC-3 slice), consumed by Hub [FEAT-H013](../../../products/hub/features/FEAT-H013-group-creation-and-stewardship.md). New SECURITY DEFINER functions + the erasure amendment + TRUNCATE revokes → schema gate at build; **no new table, no policy changes** (the invite/accept/decline RLS is already substantively correct and stays as defense-in-depth).
