# Repository tooling — the registry

**Created 2026-09-05 (Cycle COR-E W5, Audit V AC5-4 / AC5-9, GC-27); extended the same day for ADR-U053.** The repo root is tooling-only since the Phase-4 cutover (W3, PR #503): `hub/` owns the application, `supabase/` the substrate, and everything under `scripts/` and `hub/scripts/` is a tool an engineer or a hook runs by hand. This file is the **registry** of those tools. It is gate-enforced: `hub/tests/unit/platform/script-registry.test.ts` fails red on any script without a row here, on any row naming a file that no longer exists, and on any script that creates or deletes auth users whose row does not say how it tears down and censuses what it made.

**The rule behind the last clause** (Stefan, 2026-09-04 — "we do NOT want any test accounts to be left overs from testing … this needs to STOP"): every creator of accounts deletes what it created through a teardown that ends in a failing-if-not-empty census. Three pre-rebuild scripts (`cleanup-test-data.js`, `cleanup-test-users.js`, `seed-test-members.js`) that held a service-role client and acted on accounts outside that discipline were **deleted 2026-09-05** (COR-E R-12); the sanctioned paths are `hub/scripts/walk-cast.mjs`, the suite helpers' `cleanupTestUser` chain, and the integration tier's teardown census.

**Two projects, one fuse (ADR-U053, adopted 2026-09-05).** `supabase/projects.json` names the production project and the test project. `.env.local` (root and `hub/`) carries the **test** project — suites, E2E, probes, walks and the dev server default to it; `.env.production-gate.local` carries production for the schema gate's production leg only. Every database-touching script and helper runs the fuse (`scripts/lib/target.js` / `hub/tests/helpers/target.ts`): the production ref is refused unless `ALLOW_PRODUCTION=1` names the intent. `production-fuse.test.ts` sweeps the consumers. Vercel's production environment alone carries production keys at runtime.

Related, not under `scripts/`: `supabase-cli.sh` / `supabase-cli.bat` at the root wrap the Supabase CLI (`.sh` for Claude Code, `.bat` for Claude Desktop — `AGENTS.md` "Execution environment"); pass `--project-ref <ref>` for the project you mean (the CLI is not linked). Root `package.json`'s `@supabase/supabase-js` and `dotenv` devDependencies exist to serve the scripts in this table.

**Adding a script:** add its row in the same change (the gate fails red otherwise). If it touches the database, it loads its target through `scripts/lib/target.js` (the fuse gate fails red otherwise). If it creates or deletes auth users, it needs a teardown mode and a census, and its row says so.
